# Maintaining Detached Chat

- `SKILL.md` is the file an agent reads at use time. Keep it two procedures: reopen a past chat (find, skip open chats, launch clean, verify, report), and hand off work (task file, where it runs, start, check, learn how it ended, report). Launch Clean is the one window launcher, shared by reopening in both CLIs, window chats, and the window on a background chat.
- `references/codex.md` holds only what differs when the chat to reopen is a Codex one: its folder, its open check, its launch arguments, and its verification. `SKILL.md` keeps where Codex titles live, because choosing the CLI needs them before the reference is read. Give Codex differences only, never a second launcher.
- The transcript layout, title line types, the `~/.claude/sessions` registry and its `kind` field, and the fact that a helper session never registers there all come from observed Claude Code behavior, not documentation. Recheck them against a real transcript and a real launch when Claude Code changes how it stores or tracks sessions.
- The background commands, what they print, the fields and values of `claude agents --json`, worktree isolation and what a background chat commits and pushes, what survives sleep and shutdown, and the idle notice all follow Claude Code's own documentation: its CLI reference, and its pages on agent view, sessions, and cross-session messaging. Recheck each against those pages and `claude --help` before changing it.
- That a background chat an agent starts runs as a session of its own, with its own session ID, a saved transcript, and color, is an observation. The documentation says which settings and shell variables reach a background chat, and does not say this. Recheck it by starting one from an agent's shell.
- The Windows Terminal flags follow Microsoft's Windows Terminal command-line reference. `--reloadEnvironment` exists because a tab given a command line inherits the terminal process's environment by default, and a terminal the agent starts gets the agent's.
- That `codex resume` takes a session ID or a session name, with a UUID winning, follows `codex resume --help` and the developer commands page of OpenAI's Codex documentation. That page is also the source for Codex asking which directory to use when the current one differs from the chat's saved one.
- The Codex title index and its `id` and `thread_name` fields, the last line winning for a repeated `id`, the transcript path, more than one transcript file for one chat, and `cwd` on the `session_meta` and `turn_context` lines all come from reading real files, not documentation. Recheck them against a real `~/.codex` when Codex changes how it stores sessions. The state database under `~/.codex` holds the same names, but its file name carries a schema number and its `cwd` carries an extended-length path prefix, so the skill reads the index and the transcript.
- The Codex lock file as the sign of an open chat is an observation. A process other than the chat's window holds it, which fits the shared background server that `codex --help` names, and a window started without `resume` has a lock but no session ID on its command line. That the lock goes away shortly after its window stops rests on one test, in which the window's process was stopped by force. A window closed by the user was not tested. Recheck both by resuming an unimportant chat with no prompt, closing it each way, and watching the lock.
- The helper failure that Launch Clean describes is a Claude Code finding and was not reproduced for Codex. Codex goes through the same launcher because there is one launcher, and nothing in the skill says Codex needs the fresh environment.
- Handing off work is Claude Code only. `codex resume --help` shows an optional prompt, and `codex --help` lists a `queue` command for an existing session that OpenAI's documentation does not cover. Neither has been run from this skill. Before adding Codex to Hand Off Work, test with throwaway chats that a prompt given to a new chat and to a resumed chat is submitted, how a new chat's session ID is learned without a flag that sets it, what a queued message does to an open chat and to a closed one, and how the end of the work is detected.
- Test any change to the launch by reopening a real chat and confirming three things: the chat registers in `~/.claude/sessions`, the window shows color, and no transcript-saving warning appears. The agent's shell sets a no-color variable and Git variables that skip editors and prompts, so a tab that dumps its environment to a file is a quick check that none of them got through. Then reopen a real Codex chat and confirm its `codex resume` process and its lock file.
- Test any change to handing off work with throwaway chats in a scratch folder: a new window chat and a past chat continued in a window, each with the one-line prompt, a background chat started and then continued with `--bg --resume`, a window opened on it with `attach`, a message and an idle notice, and its entry in `claude agents --json --all`. Stop and remove the test chats afterward.
- Model, effort, and name are chosen before this skill runs, with one fallback rule in Write The Task File for when none was.
- Keep machine paths, session IDs, and chat titles out of the skill.
- Bump `metadata.version` on every change.
