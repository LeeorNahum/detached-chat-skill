# Maintaining Detached Chat

- `SKILL.md` is the only file an agent reads at use time. Keep it two procedures: reopen a past chat (find, skip open chats, launch clean, verify, report), and hand off work (task file, where it runs, start, check, learn how it ended, report). Launch Clean is the one window launcher, shared by reopening, window chats, and the window on a background chat.
- The transcript layout, title line types, the `~/.claude/sessions` registry and its `kind` field, and the fact that a helper session never registers there all come from observed Claude Code behavior, not documentation. Recheck them against a real transcript and a real launch when Claude Code changes how it stores or tracks sessions.
- The background commands, what they print, the fields and values of `claude agents --json`, worktree isolation and what a background chat commits and pushes, what survives sleep and shutdown, and the idle notice all follow Claude Code's own documentation: its CLI reference, and its pages on agent view, sessions, and cross-session messaging. Recheck each against those pages and `claude --help` before changing it.
- That a background chat an agent starts runs as a session of its own, with its own session ID, a saved transcript, and color, is an observation. The documentation says which settings and shell variables reach a background chat, and does not say this. Recheck it by starting one from an agent's shell.
- The Windows Terminal flags follow Microsoft's Windows Terminal command-line reference. `--reloadEnvironment` exists because a tab given a command line inherits the terminal process's environment by default, and a terminal the agent starts gets the agent's.
- Test any change to the launch by reopening a real chat and confirming three things: the chat registers in `~/.claude/sessions`, the window shows color, and no transcript-saving warning appears. The agent's shell sets a no-color variable and Git variables that skip editors and prompts, so a tab that dumps its environment to a file is a quick check that none of them got through.
- Test any change to handing off work with throwaway chats in a scratch folder: a new window chat and a past chat continued in a window, each with the one-line prompt, a background chat started and then continued with `--bg --resume`, a window opened on it with `attach`, a message and an idle notice, and its entry in `claude agents --json --all`. Stop and remove the test chats afterward.
- Model, effort, and name are chosen before this skill runs, with one fallback rule in Write The Task File for when none was.
- Keep machine paths, session IDs, and chat titles out of the skill.
- Bump `metadata.version` on every change.
